## Demonstrated contracts and security

Three exported schemas and standalone validators; types generated from the same union. 1.0.0/1.1.0 validated before migration, current copies without loss of text, notes or extensions; empty pluginSettings added to migrated copies. Atomic rejection of missing asset or link references, extra or missing builtin data, oversized sources and syntactically invalid APIs and versions. Unknown plugin data versions stay opaque with a placeholder; nothing is loaded from the JSON. The blocks capability is required only when rich content or plugin settings use it.

A single DOMPurify pipeline for HTML and SVG, marked before the same pipeline; text through textContent. Browser tests on mount, updateDocument and direct renderer updates: script, onerror, javascript and disguised URLs, SVG foreignObject, SMIL and external href, active CSS, Markdown HTML, `</script>` and prototype keys stay inert. Assertions on the allowed DOM, no global marker and no hostile requests. SVG IDs rewritten per instance and SVG image assets sanitized before the new URL.

Real KaTeX with MathML, local fonts, `trust:false`, maxExpand 500/maxSize 20 and per-render macros. Real formulas rendered and inspected; macros defined in one block do not appear in the next; recursion and trust extensions produce a fallback without network. The styles generated by KaTeX are distinct from the user source, whose styles are always removed.

ZIP: consistent central and local headers, CRC and SHA-256, incremental inflate with an effective limit, registered entries without overlaps or hidden files. Negative tests for traversal, slash and backslash, percent encoding, absolute paths, non-canonical Unicode, duplicates, symlinks, entry count, file, JSON and total size and false sizes after inflate, wrong MIME types and digests, missing resources, extra files and a corrupted CRC. A failed opening leaves the current work intact. The manifest separates the original `path` from the portable `entry` under `assets/<id>/`, keeping JSON with files alongside without rewriting paths. Limits: 50 MiB per file, 200 MiB decompressed in total, 10 MiB per JSON and 10,000 entries. ZIP64, encryption, multi-disk archives and explicit directories are rejected.

## Media, plugins and persistence

[Chromium media tests](content-media-chromium.json), [Firefox](content-media-firefox.json), [WebKit](content-media-webkit.json): local WAV and H.264 actually advance; 320×180 video, native controls, an SVG poster and VTT captions. A refused play shows a useful action; `mediaerror` exposes scene, block, asset and diagnostic. A corrupted local MP4 causes a real decoder error and the typed event, without a synthetic dispatch. Exit with stop resets, pause keeps the time; the second instance stays still. Destroy stops loads and media, aborts and revokes the leases. Instrumented test: zero Blob URLs left after the teardown of the media renderers in both instances. The editor preview is muted.

These are browser control and playback tests, **not listening tests** or sample-accurate audio sync. The decoder may refuse other files or codecs: MIME type and minimal sniffing do not certify the whole container; the fallback is explicit.

Plugin SDK 1.0.0, a local host registry, data and settings schemas with trusted predicates, services and a signal. An original offline badge with a separate inspector. Throwing factories, mounts and updates are isolated; abort and unregister remove subscriptions; faulty dispose or destroy calls do not prevent the other teardowns. Namespaced events verified and a missing or incompatible plugin preserved in the roundtrip. JS plugin code has the page's authority and is trusted, without a sandbox. Data migrations are explicit host functions, never automatic when a plugin is missing. Capture stays false in the sample: there is no 0.4 export.

Embeds off by default; an authorized HTTPS origin and a further consent, an empty sandbox without allow-same-origin or scripts, a restrictive CSP attribute and revocation. The tests verify consent, sandbox and the absence of execution. **Enforcement of the frame's CSP attribute is not uniform across browsers**: the verified boundary is the script-free sandbox; universal isolation of passive remote subresources is not guaranteed. Studio forbids every frame. No embed with scripts, MIDI or OSC is supported or required.

[Chromium storage](content-storage-chromium.json), [Firefox](content-storage-firefox.json), [WebKit](content-storage-webkit.json): revisions and asset bytes and MIME types in the same IDB v2 commit. Reads recreate Blobs. A removed resource stays in the earlier revisions; only after eviction from all of the last ten revisions is it collected. A quota error injected into assets.put also rolls back documents and recovery; no partial revision. The regressions for denied storage, conflicts across two tabs and recovery stay active. Manually linking a missing resource, reload and recovery are tested from the UI.

## Fixed errors, limits and handoff

Defects found and fixed: an SVG inlined and minified by Vite with a different digest, which broke poster and captions; inline fonts incompatible with the Studio CSP; WebKit IDB UnknownError and a hanging transaction when cloning Blob/File directly (bytes and MIME types are persisted instead); plugin teardown that could stop on an exception; the missing public mediaerror event; poster completion that cleared a decoding error already emitted (now persistent until success or a source change). The first failed runs are diagnostic. The tests now wait for metadata before the media gesture, for the import to finish and for resources to load before instrumenting leases, instead of assuming identical load times across browsers.

The gallery resources are original and synthetic, [CC0](../../examples/content-gallery/LICENSE.md). DOMPurify MPL-2.0 OR Apache-2.0; marked, KaTeX and fflate MIT, real metadata and licences consulted. No change to LICENSE and no inference of the project's SPDX identifier.

Not run: installed Safari, Chrome and Edge, physical mobile devices, a real screen reader, listening tests, MIDI hardware, OSC, heap after GC and p95 benchmarks. The earlier Linux CI remains evidence for 0.1 only. Studio with every renderer produces a Vite warning for chunks >500 kB: the minimal core/player bundle passes its own budget, but the performance budget of the complete app is not claimed. Offline here means an app already served from a local host with the content available: no PWA, cached shell or standalone HTML anticipated.

For 0.5, preserve schema 1.2.0, canonical sources and assets, migrations, the pipeline and the regressions. Implement then profiles, capture, export and output manifests, without inferring PDF, video or standalone HTML support from browser playback alone. No later phase started.
