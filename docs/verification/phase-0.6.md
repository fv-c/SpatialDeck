## Presenter

`presenter.spec.ts` (production Studio, a real pop-up):

- **Presenter** opens the audience window on the click; status «audience window connected»; private notes of the scene in the console; branch choices of A with two buttons; «Explore B» takes both windows to B; arrows on the console forwards and back (D, B); an arrow in the audience window becomes a request to the console (D); notes absent from the DOM and the text of the audience window; the console previews muted; the Start/Pause (value frozen)/Reset timer.
- Reloading the audience window: snapshot with the history `["A","C"]` rebuilt; reloading the console: «Resume presenter view» disabled until the project is reopened, then the session adopts the same audience window.
- Ignored: a message from the window itself (wrong source), a wrong session, a new epoch without a snapshot, a command outside the protocol, an audience window opened from another origin (it stays «waiting», player not mounted).
- Blocked pop-up (`window.open` → `null`): instructions, and **Present in this tab** opens the single-window presentation without notes.
- Audience page opened on its own: it explains how to open it from the Presenter button.

Three defects found by the tests and fixed: the choice buttons of the console's preview player navigated without forwarding the command (they now go through `delegate`); resuming after a reload sent an empty document (it now requires the project to be open); in WebKit, after the presenter tab reloaded, the snapshot did not reach the audience window. Diagnosed with a probe in the WebKit runner: the audience window's hello arrives with an `event.source` pointing to the presenter tab itself, and a reference obtained from `event.source` delivers no messages, while the window found with `window.open("", name)` receives them with the correct sender. Resuming now finds the window by name on the click, and a handshake with a random nonce (the presenter's `probe`, the nonce echoed by the audience window) replaces source identity where the engine reports it wrongly; 7 unit tests (`presenter.test.ts`) cover schema, note-free snapshots, sequences, foreign sources and the wrong-source case.

## Limits and debt

- Publication blocked by the unverified ownership of the npm scope; `engines.node: ">=24"` tested only with 24.22.0.
- PDF and video tested with Chromium 156 on macOS 14; WebKit and Firefox open HTML and builds but are not capture engines.
- In the screenshots of the headless WebKit runner (Playwright 1.61.1, macOS 14) scenes rotated in 3D are painted flattened (for example the flow scene rotated by 25° in the exported HTML appears compressed by about cos²25°), while the measured geometry (`getBoundingClientRect`, landmarks within 1 px) matches the core projection. The playground on `/core` looks the same: a pre-existing limit of that runner's painting, not introduced by the exports; the WebKit tests rely on geometry, not on the pixels of 3D poses. Real Safari, mobile devices and screen readers not tested. The presenter view is not available in `file://` HTML; no guarantee against operating-system mirroring, and the choice of monitor stays with the browser.
- In the PDF, the text of scenes seen in perspective may be rasterized by Chromium; the visit's page stays faithful to the player.
- The video has no audio or dynamic media; H.264 is not offered; pixel identity holds only in the same fixed environment.
- `readArchive` still keeps the whole compressed archive in memory in addition to the Blobs; `writeArchive` keeps the compressed chunks until the final Blob.
- The realistic-consumer threshold is measured but not set (before 1.0).
- In CI, the Linux WebKit of Playwright 1.64.1 reports `style-src-attr` for the native `<select>` elements of the playground page (outside the player): a targeted exception in the CSP test, see «Linux CI».
